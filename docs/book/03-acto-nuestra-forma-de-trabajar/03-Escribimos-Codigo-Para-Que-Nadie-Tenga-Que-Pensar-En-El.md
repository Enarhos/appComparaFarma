# Escribimos código para que nadie tenga que pensar en él

El mejor software no es el que demuestra cuánto saben quienes lo desarrollaron.

Es aquel que permite que las personas logren su objetivo sin detenerse a pensar cómo funciona.

Cuando alguien utiliza ComparaFarma, no debería notar nuestra arquitectura.

No debería preguntarse qué lenguaje utilizamos.

No debería percibir la complejidad de nuestros sistemas.

Solo debería sentir que todo funciona como esperaba.

Ese es nuestro trabajo.

---

## La complejidad nos pertenece a nosotros

Toda solución tecnológica implica complejidad.

Servicios.

Bases de datos.

Integraciones.

Infraestructura.

Modelos de inteligencia artificial.

APIs.

Procesos.

La complejidad es inevitable.

Lo que sí podemos decidir es dónde vivirán esas dificultades.

Nuestra decisión es clara.

La complejidad debe permanecer dentro de la organización.

Nunca en la experiencia de las personas.

Cada vez que un usuario necesita "aprender" a utilizar una funcionalidad, debemos preguntarnos si realmente hicimos bien nuestro trabajo.

---

## El código es una herramienta, no una obra de arte

Nos sentimos orgullosos de escribir buen software.

Pero nunca escribiremos código para impresionar a otros desarrolladores.

Escribiremos código para que pueda ser entendido, mantenido y mejorado durante muchos años.

El software elegante no es el más ingenioso.

Es el más claro.

Cada línea de código debe facilitar el trabajo de quien la leerá mañana.

Aunque ese alguien seamos nosotros mismos.

---

## Programamos para el largo plazo

Es posible construir algo que funcione hoy.

Es mucho más difícil construir algo que siga funcionando dentro de diez años.

Cada decisión técnica debe considerar el futuro.

La velocidad tiene valor.

Pero la deuda técnica también tiene consecuencias.

Sabemos que habrá momentos en que debamos asumir compromisos para avanzar.

Cuando ocurra, los reconoceremos explícitamente.

Nunca esconderemos deuda técnica bajo la apariencia de trabajo terminado.

Todo compromiso deberá tener un plan para ser resuelto.

---

## La calidad también es una forma de respeto

Los errores existen.

Ningún sistema complejo está completamente libre de ellos.

Lo que sí podemos decidir es nuestra actitud frente a los errores.

No culpamos a las personas.

Buscamos comprender el sistema que permitió que ocurrieran.

Cada incidente debe dejarnos un aprendizaje.

Cada aprendizaje debe convertirse en una mejora.

Cada mejora debe reducir la posibilidad de que el mismo problema vuelva a repetirse.

La calidad no se alcanza evitando equivocaciones.

Se alcanza aprendiendo de ellas.

---

## Automatizamos para proteger el tiempo

Las tareas repetitivas consumen un recurso que nunca podremos recuperar.

El tiempo.

Siempre que sea razonable, automatizaremos aquello que no aporte valor al criterio humano.

No para reemplazar personas.

Sino para permitirles dedicar su talento a resolver problemas que realmente requieren inteligencia, creatividad y juicio.

La automatización bien utilizada no reduce el valor del trabajo humano.

Lo aumenta.

---

## Construimos sistemas que sobrevivan a sus autores

Todo software debería poder continuar evolucionando aunque quienes lo escribieron ya no estén.

El conocimiento no puede vivir únicamente en la memoria de una persona.

Debe vivir en la documentación.

En las pruebas.

En la arquitectura.

En las decisiones registradas.

Y en el propio código.

Una organización madura no depende de héroes.

Depende de sistemas que permiten que muchas personas contribuyan con confianza.

---

## Nuestro compromiso

Escribiremos código que sirva a las personas antes que a nuestro ego.

Preferiremos la claridad antes que la complejidad innecesaria.

Documentaremos las decisiones importantes.

Automatizaremos aquello que no requiera criterio humano.

Y construiremos sistemas pensando en quienes continuarán este trabajo después de nosotros.

Porque el mejor software no es el que recibe más elogios.

Es aquel que permite que las personas olviden que existe.
