# ACTA DE SESIÓN
## ComparaFarma – Cierre de Arquitectura e Inicio de Implementación

**Fecha:** 07 de agosto de 2026  
**Proyecto:** ComparaFarma – Plataforma de Inteligencia Farmacéutica  
**Participantes:** Mario Lillo (Product Owner), ChatGPT (CTO)

---

# Objetivo de la sesión

Concluir la etapa de Arquitectura de la Plataforma y preparar el inicio de la implementación de la convergencia entre el Cliente Mobile y el Cliente Web.

---

# Acuerdos alcanzados

## 1. Cambio de visión del proyecto

Se confirma oficialmente que ComparaFarma deja de entenderse como dos aplicaciones independientes.

A partir de esta sesión el proyecto se define como:

> **Una Plataforma de Inteligencia Farmacéutica con múltiples clientes.**

Los componentes oficiales pasan a denominarse:

- Cliente Mobile
- Cliente Web
- Servicios de Plataforma

Se evita continuar utilizando la separación tradicional:

- Mobile
- Web
- Backend

como si fueran productos distintos.

---

## 2. Arquitectura declarada oficialmente completa

Se aprueba como línea base de arquitectura la siguiente documentación:

- CURRENT_PLATFORM_ASSESSMENT.md
- USER_DOMAIN_MODEL.md
- IDENTITY_INTEGRATION_PLAN.md
- PLATFORM_CAPABILITY_MODEL.md
- PLATFORM_CONVERGENCE_MASTER_PLAN.md

Esta documentación constituye la **Architecture Baseline v1.0** del proyecto.

A partir de este punto no se generarán nuevos documentos estratégicos generales, salvo mediante RFC.

---

## 3. Modelo de Usuario

Se aprueba el modelo conceptual compuesto por:

- Persona
- Instalación
- Identidad
- Perfil
- Usuario

Se acuerda que toda nueva funcionalidad deberá clasificarse explícitamente como perteneciente a:

- Usuario
- Dispositivo
- Plataforma

antes de comenzar cualquier implementación.

---

## 4. Modelo de Capacidades

Se aprueba el Capability Model compuesto por siete dominios:

- Descubrir
- Comparar
- Recordar
- Identidad
- Monetizar
- Inteligencia
- Operar

Este modelo pasa a ser la referencia oficial para organizar el roadmap del producto.

---

## 5. Roadmap de convergencia

Se aprueba la convergencia incremental.

La Fase 1 queda dividida en:

### Fase 1A

Identity Foundation

### Fase 1B

Profile Foundation

Posteriormente continuarán las capacidades:

- Favoritos
- Comparaciones
- Alertas
- Premium
- Historial (Opt-In)

---

## 6. Decisión sobre autenticación

Se confirma el siguiente principio:

La autenticación identifica una Cuenta ComparaFarma.

No determina directamente las funcionalidades disponibles.

Las capacidades del usuario serán determinadas por la Plataforma.

---

## 7. Separación entre Identidad y Suscripción

Se acuerda separar conceptualmente:

### Identity

Quién es el usuario.

### Subscription

Quién procesó el pago.

### Entitlements

Qué beneficios posee.

### Capabilities

Qué funcionalidades puede utilizar.

Esta separación permitirá soportar múltiples proveedores de autenticación y múltiples proveedores de pago sin modificar el dominio.

---

## 8. Modelo comercial

Se mantiene la estrategia definida previamente.

### Cliente Mobile

Autenticación:

Cuenta ComparaFarma

Suscripción:

Google Play Billing

---

### Cliente Web

Autenticación:

Cuenta ComparaFarma

Suscripción:

Proveedor propio (Flow inicialmente).

---

En ambos casos:

La Plataforma será la única fuente de verdad para determinar el estado Premium y los Entitlements.

---

## 9. Entitlement Service

Se acuerda introducir el concepto de:

**Entitlement Service**

como servicio responsable de determinar las capacidades disponibles para un usuario.

No será responsabilidad de:

- Google Play
- Flow
- Stripe
- Apple

determinar qué funcionalidades puede utilizar el usuario.

---

## 10. Inicio de la implementación

Se declara oficialmente cerrada la etapa de Arquitectura.

El proyecto pasa a la etapa de Implementación.

# Conclusión

La sesión marca un hito relevante en la evolución del proyecto.

ComparaFarma deja de concebirse como una aplicación móvil complementada por una web y pasa a estructurarse como una **Plataforma de Inteligencia Farmacéutica**, con una arquitectura común, un modelo de dominio unificado y una estrategia formal de convergencia entre sus distintos clientes.

La Architecture Baseline v1.0 queda establecida como referencia oficial para toda implementación futura.
