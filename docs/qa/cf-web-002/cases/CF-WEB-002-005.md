# CF-WEB-002-005 — Cada visita a una ficha resolvía el slug dos veces, con dos búsquedas independientes

| Campo | Valor |
|---|---|
| **Severidad** | P2 — costo y consistencia |
| **Clasificación** | `INCONSISTENT_RESOLUTION` |
| **Encontrado** | Durante la revisión de arquitectura (Fase 4), no por el arnés |

## Comportamiento observado

`web/src/app/medicamento/[slug]/page.tsx` llamaba a `resolveMedicationBySlug`
dos veces por request: una en `generateMetadata` y otra en el componente de
página. Cada llamada dispara su propia búsqueda en vivo contra las 9 farmacias.

Dos consecuencias:

1. **Costo.** Dos búsquedas completas por visita a una ficha. Con la escalera de
   recuperación de este ticket habrían sido hasta cuatro.
2. **Inconsistencia.** Las dos resoluciones son independientes y el catálogo
   cambia entre llamadas. La ficha podía renderizar un producto mientras el
   `<title>`, el `description` y el `<link rel="canonical">` describían otro; o
   el `<title>` podía decir "Medicamento no encontrado" sobre una ficha que sí
   resolvió (y al revés). Es exactamente la clase de inestabilidad que ya
   documenta `resolveMedication.ts` a propósito del `canonicalName` que
   `mergeDuplicates` puede elegir distinto entre dos búsquedas.

## Corrección

```ts
const resolveOnce = cache(resolveMedicationBySlug);
```

`cache()` de React memoiza por request en el App Router: `generateMetadata` y el
componente de página ven exactamente la misma resolución. Es el patrón que la
propia documentación de Next recomienda para deduplicar trabajo entre esas dos
funciones.

Efecto neto sobre el número de búsquedas por visita, contando la escalera de
recuperación de CF-WEB-002-001:

| | Búsquedas por visita |
|---|---|
| Antes | 2 (una por resolución) |
| Con la escalera, sin `cache()` | 2 a 4 |
| Con la escalera y `cache()` | **1 a 2** |

El caso mayoritario es 1: la consulta de cabecera (`"tapsin"`, `"ambroxol"`) es
justamente la que los usuarios escriben, así que suele encontrar la caché del
backend caliente.

## Verificación

- `pnpm --filter web test` — las 36 suites siguen verdes, incluida
  `page.test.tsx`, que ejercita `generateMetadata` y el componente por separado.
- El `canonical` sigue calculándose sobre el mismo `canonicalSlug` que decide el
  redirect, ahora con la garantía de que ambos vienen de la MISMA resolución.
